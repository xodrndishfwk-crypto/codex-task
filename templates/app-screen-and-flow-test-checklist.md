|---|---|---|---|---|---|---|

## 필수 확인

- [ ] 안내된 명령으로 앱이 실행된다.
- [ ] 모든 필수 화면에 이동할 수 있다.
- [ ] 핵심 사용자 흐름을 처음부터 끝까지 완료할 수 있다.
- [ ] 빈 입력과 잘못된 입력을 처리한다.
- [ ] 로딩·빈 화면·오류·완료 상태가 필요한 곳에 표시된다.
- [ ] 모바일 화면에서 글자와 버튼이 잘리거나 겹치지 않는다.
- [ ] 뒤로 가기·취소·재시도·반복 실행이 필요한 방식으로 동작한다.
- [ ] 저장이 필요한 데이터는 화면 이동·새로고침·재실행 후 요구사항대로 유지된다.
- [ ] 자동 검사와 빌드 결과를 기록했다.
- [ ] 확인하지 못한 동작과 남은 위험을 기록했다.

## 사용자 관점의 화면 구조 검토

과제 README와 담당자 답변의 실제 조건에 맞게 상황을 고른다. 정해진 화면 틀이나 새 기능을 강요하지 않는다.

- [ ] 다음 행동과 그 행동에 필요한 정보를 사용자가 찾을 수 있다.
- [ ] 관련 입력·설명·결과가 함께 이해되며 핵심 결과와 부가정보가 구분된다.
- [ ] 적용된 조건을 확인할 수 있어 이전 화면을 기억하거나 결과의 기준을 추측할 필요가 없다.
- [ ] 이름·현재 상태·완료 안내·빈 결과·오류 안내가 일관되고 다음 행동을 알려준다.
- [ ] 비교가 필요한 과제는 관련 기준과 단위를 일관되게 보여준다.
- [ ] 명세서 위반과 사용성 개선 의견을 구분하고, 미정 업무 기준은 질문으로 연결했다.
- [ ] 코드 확인·미리보기·실제 조작을 구분하고 확인하지 못한 항목은 미검증으로 남겼다.

| 요구사항·출처 또는 사용 상황 | 화면·위치 | 관찰 내용 | 사용자에게 미치는 영향 | 구분 | 확인 방법·증거 | 조치 또는 질문 ID |
|---|---|---|---|---|---|---|
|  |  |  |  | 명세서 위반 / 사용성 개선 의견 / 업무 기준 확인 필요 |  |  |

발견 사항이 없으면 점검한 범위와 증거를 적는다. 확인할 수 없었던 항목은 미검증 사유와 남은 위험을 적는다. 사용자 판단이 필요한 질문은 단계별 진행보고에 같은 ID로 누적한다.
