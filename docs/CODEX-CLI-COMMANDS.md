# Bash에서 사용하는 Codex 명령어

과제 폴더에서 실행하는 Codex CLI 명령어와 용도를 정리한 참고 문서다. 설치 버전에 따라 지원하는 명령어와 옵션이 다를 수 있으므로 실제 환경에서는 `codex --help`와 각 명령어의 `--help`를 확인한다. 시험에서는 제공된 환경과 공식 지침을 우선한다.

## 기본 명령어

| 명령어 | 용도 |
|---|---|
| `codex` | 현재 폴더에서 대화형 Codex 시작 |
| `codex "요청 내용"` | 첫 요청을 넣고 대화형 Codex 시작 |
| `codex -C /path/to/project` | 지정한 폴더를 작업 위치로 사용 |
| `codex resume` | 이전 대화를 목록에서 골라 이어가기 |
| `codex resume --last` | 가장 최근 대화 이어가기 |
| `codex fork --last` | 최근 대화를 분기해 새 대화로 시작 |
| `codex --help` | 전체 명령어와 옵션 확인 |
| `codex --version` | 설치 버전 확인 |
| `codex resume --help` | 특정 명령어의 자세한 사용법 확인 |

`codex`는 새 대화를 시작하고, `codex resume`는 이전 대화의 맥락을 이어간다.

## 상황에 따라 사용하는 명령어

| 명령어 | 용도 |
|---|---|
| `codex --no-alt-screen` | 터미널 스크롤 기록을 유지하는 방식으로 실행 |
| `codex -s read-only "요청 내용"` | 읽기 전용으로 조사하도록 실행 |
| `codex -i screenshot.png "이 화면을 설명해줘"` | 시작 요청에 로컬 이미지 첨부 |
| `codex review` | 코드 리뷰를 비대화형으로 실행 |
| `codex exec "요청 내용"` | 요청을 비대화형으로 실행하고 종료 |
| `codex login` | 로그인 |
| `codex logout` | 로그아웃 |

읽기 전용 모드에서는 설명 문서나 진행보고 MD를 저장하는 작업도 제한된다. 이 도구 모음의 문서 생성 흐름을 사용할 때는 일반 `codex`로 시작한다.

## 이 도구 모음으로 시작하기

실제 과제 README와 제공 파일이 있는 과제 폴더에서, `codex-task/`를 가져온 상태로 실행한다.

```bash
codex "codex-task/AGENTS.md와 codex-task/START-HERE.md를 읽고 시작해."
```

이미 Codex 대화창이 열려 있다면 Bash에서 다시 실행할 필요 없이 대화창에 다음 문장을 입력한다.

```text
codex-task/AGENTS.md와 codex-task/START-HERE.md를 읽고 시작해.
```

시작 절차는 실제 과제 README 조사, `README-이해하기.md` 작성·제시, 중요 질문과 작업 계획, 조사 보고서 작성으로 연결된다. 구현은 이후 진행 지시에 따라 이어간다.

터미널을 닫았다가 기존 작업으로 돌아오려면 다음 명령어로 대화를 선택한다.

```bash
codex resume
```

## 도움말 확인 예시

```bash
codex --help
codex exec --help
codex review --help
codex resume --help
```

## Codex 대화창 명령과 병렬 작업

Bash 명령과 Codex 대화창의 슬래시 명령은 입력하는 곳이 다르다.

| 입력 내용 | 입력 위치 | 역할 |
|---|---|---|
| `codex` | Bash | Codex 대화형 CLI 시작 |
| `/subagents` | 실행 중인 Codex 대화 입력창 | 에이전트 작업을 확인하고 다른 에이전트 대화로 전환 |
| 서브에이전트 두 개로 나눠 조사해줘 | Codex 대화 입력창 | 자연어로 병렬 작업 분담 요청 |

`/subagents` 자체는 병렬 작업을 생성하는 명령이 아니다. 지원되는 환경에서는 먼저 자연어로 작업을 요청하고, 실행 중인 에이전트는 `/subagents`로 확인한다.

병렬 조사 요청 예시:

```text
서브에이전트 두 개를 사용해 병렬로 조사해줘.
하나는 요구사항 누락을, 다른 하나는 기존 코드와 테스트를 확인해.
파일은 수정하지 말고, 두 결과가 모두 나오면 근거 파일과 함께 종합해줘.
```

메인 Codex가 작업을 나눠 맡기고 결과를 모은다. 방향 변경이나 중단이 필요하면 메인 대화에서 해당 에이전트의 작업을 바꾸거나 중단해 달라고 요청한다. 여러 에이전트가 같은 파일을 수정하면 충돌할 수 있으므로 처음에는 독립적인 조사·검토 작업에 적용하기 좋다. 에이전트가 각각 작업하므로 토큰 사용량은 늘어날 수 있다.

### fork와의 차이

- `codex resume`: 기존 대화 이어가기.
- `codex fork --last`: 기존 기록에서 새 대화로 분기. 자동 병렬 작업 분담·결과 취합 기능은 아니다.
- 서브에이전트: 메인 Codex가 하위 작업을 위임하고 결과를 취합.
- 터미널 여러 개에서 Codex 실행: 각각 독립적으로 작업하며 사용자가 역할과 결과를 관리.

대화 분기는 파일 복사를 뜻하지 않는다. 같은 작업 폴더를 쓰면 파일을 공유한다.

### 시험에서의 사용 범위

기능 지원 여부와 시험 허용 여부는 별개다. 현재 `AGENTS.md`는 제공된 Codex 이외의 AI·에이전트 서비스를 금지하지만, 제공된 Codex 내부 서브에이전트의 허용 여부를 명시하지 않는다. 시험 공식 안내에서 허용 범위를 확인하고, 이 문서를 허용 근거로 해석하지 않는다. 문서 추가는 자동 병렬 실행 설정을 활성화하지 않는다.

설치 버전과 환경에 따라 명령이 다를 수 있다. Codex 대화 입력창에서 `/`를 입력해 제공되는 명령 목록을 확인한다.
