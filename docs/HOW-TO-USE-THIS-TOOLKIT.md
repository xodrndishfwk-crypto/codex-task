# 이 도구 모음을 사용하는 방법

## 1. 시작 전

최신 공식 공지, 과제 README, 제출 지침을 읽는다. 공개 저장소 사용이 허용되더라도 특정 자료와 기능이 허용되는지는 별개이므로 범위를 확인한다.

## 2. 작업 공간 파악

Codex에 기존 파일, 실행 명령, 테스트, 변경 상태를 읽기 전용으로 조사하도록 요청한다. 이 단계에서 설치, 업로드, 대규모 변경을 시작하지 않는다.

## 3. 요구사항 확정

`skills/list-required-results-and-rules/SKILL.md`, `skills/prepare-clear-business-questions/SKILL.md`, `templates/required-results-and-rules.md`를 사용한다. 모호한 내용은 업무 담당자에게 한 질문에 한 결정만 담아 묻는다.

예시:

```text
필수 사용자 흐름과 제출물을 과제 원문에서 추출하고, 명시된 사실과 가정을
분리해 requirements.md에 작성해. 결과에 영향을 주는 모호함은 담당자 질문으로
정리하고, 답변 전에는 범위를 임의로 확장하지 마.
```

## 4. 계획과 구현

`skills/plan-small-steps-and-checks/SKILL.md`, `skills/plan-time-and-stop-points/SKILL.md`, `templates/step-by-step-work-plan.md`를 사용한다. 각 단계는 로컬 검증 방법을 포함한다. 작은 변경 후 테스트하는 흐름을 반복하고 `templates/decisions-and-work-log.md`에 중요한 결정과 증거를 남긴다.

## 5. 실패 대응

`skills/find-and-fix-code-errors/SKILL.md`를 사용해 재현, 증거, 가설, 최소 수정, 회귀 검증 순서로 진행한다. 로그를 외부로 보내지 않는다.

## 6. 최종 검증과 기록

`skills/test-results-against-requirements/SKILL.md`, `skills/write-result-and-test-report/SKILL.md`, `templates/test-results-and-evidence.md`를 사용한다. `skills/check-everything-before-submit/SKILL.md`와 `templates/work-explanation-notes.md`로 본인이 작업을 설명할 수 있는지 점검하고, 마지막으로 `templates/final-submission-checklist.md`를 확인한다. 제출 후 후속 서술형에서는 AI를 사용하지 않는다.

## 금지 도구가 제안될 때

즉시 중단하고 로컬 대안을 찾는다. Computer Use, Astra, 별도 AI/API, 외부 전송이 없으면 완료할 수 없는 경우에는 임의로 우회하지 말고 사용자에게 보고한다.
