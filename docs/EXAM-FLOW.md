# 시험 진행 흐름

## 시험의 성격

이 시험은 제공된 웹 IDE에서 실무형 과제를 수행하며 AI 활용 역량과 문제 해결 과정을 함께 평가한다. 과제의 구체적인 분야와 산출물은 시험 당일 README와 과제 안내를 기준으로 확인한다.

평가 가능한 흔적에는 내장 AI·Codex·실무자 에이전트 대화, CLI 세션과 AI 설정, Git 로그와 diff, 테스트 결과, 코드·계획·협업 기록이 포함될 수 있다. 결과물뿐 아니라 요구사항을 확인하고 AI 결과를 검증한 과정이 중요하다.

## 역할 구분

| 대상 | 문의 내용 |
|---|---|
| 과제 README | 목표, 필수 조건, 제출물의 기준 |
| 실무자 에이전트 | 업무 맥락, 사용자, 우선순위, 제품 결정 |
| Codex | 조사, 구현, 테스트, 문서 작성 지원 |
| Cofa Helper | 화면 사용법과 제출 절차 |
| 문제 신고 | 접속, 감독, 반복 오류, 플랫폼 장애 |

## 권장 흐름

1. README, 파일 구조, 실행법, 제출물을 확인한다.
2. 모호함을 실무자 질문으로 정리하고 수용 기준을 만든다.
3. 핵심 흐름이 가장 빨리 동작하는 계획부터 실행한다.
4. Codex의 변경을 diff, 실행 결과, 테스트, Browser 미리보기로 직접 검증한다.
5. 결정과 증거를 작업 일지에 남긴다.
6. 문서와 알려진 한계를 정리하고 제출 미리보기를 확인한다.
7. 제출 전에 본인이 핵심 결정과 검증 결과를 설명할 수 있는지 점검한다.

## 후속 서술형

제출물이 확정된 뒤 작업 기록 기반 문항이 준비될 수 있다. 문항마다 제한 시간이 있으며 이전 문항으로 돌아갈 수 없다. 이 단계에서는 AI와 복사·붙여넣기를 사용하지 않고 본인의 말로 직접 답한다. 질문의 전제가 실제 구현과 다르면 그 차이를 밝히고 실제 작업을 설명한다.

## 피해야 할 패턴

- 요구사항 확인 없이 큰 프로그램부터 생성하기
- Codex 출력이나 테스트 통과 문구를 직접 확인하지 않고 믿기
- 핵심 기능보다 장식, 프레임워크 교체, 과도한 리팩터링을 우선하기
- 같은 실패 요청을 반복해 시간과 토큰을 소모하기
- 실행하지 않은 테스트와 존재하지 않는 기능을 문서에 쓰기
- 외부 자료로 결과물을 통째 대체하거나 작업물을 외부로 보내기
- 제출 직전까지 구현하다 저장, 문서, 검증 시간을 잃기
